## Public Application Catalog

The SORT Framework defines a set of structural risk assessment applications organized by domain. These applications represent scoped analytical perspectives designed to support architectural and operational decision-making in AI infrastructure, complex systems, governance, and related contexts.

### Strategic Architecture

The catalog distinguishes two fundamental levels:

| Level | Character | Target Audience |
|-------|-----------|-----------------|
| **Operative** | Runtime-proximate, technically tangible, demo-capable | Engineering, Platform, Infrastructure Teams |
| **Sovereign** | Structurally diagnostic, capital- and sovereignty-relevant | Board, Government, Strategy, Institutional Investors |

**Operative Core-3** (primary entry points): ai.01 (Interconnect Stability Control), ai.04 (Runtime Control Coherence), ai.13 (Agentic System Stability)

**Sovereign Meta-Level**: sov.01 (Sovereign Infrastructure Stability & Bottleneck Risk Control)

### Catalog Structure

| Artifact | Purpose | Location |
|----------|---------|----------|

### What the Catalog Contains

Each application entry defines:

- **Application ID** — Unique identifier within the SORT namespace (sov.01, ai.01–ai.21, cx.01–cx.04, qs.01–qs.03, cosmo.01–cosmo.06)
- **Domain** — Functional classification (sovereign, ai-systems, complex-systems, quantum-systems, cosmology)
- **Maturity** — Public visibility status
- **Title** — Application name
- **One-liner** — Brief description of the assessment focus

### Relationship to Other Artifacts

The catalog is distinct from:

- **Articles and Whitepapers** — Explanatory publications providing theoretical context
- **Architecture Risk Assessment References** — Paid analytical engagements applying catalog definitions to specific contexts
- **MOCK v4 Architecture** — Structural reference for the SORT v6 framework itself
- **Lizenzmatrix** — Internal IP strategy and commercial prioritization

The catalog defines *what assessment capabilities exist*. Articles explain *why they work*. Assessment references apply them *to specific systems*.

### Usage Notes

- The JSON catalog is the authoritative source for application metadata
- The overview document provides executive-level orientation
- Public definition does not imply immediate availability for all engagement types
- No implementation guidance or operational blueprints are included
- Operative Core-3 applications are demo-capable and article-driven
- sov.01 is positioned for strategic pull, not active sales
